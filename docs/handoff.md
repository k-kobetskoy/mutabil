## Как работать на этой машине (Windows)

- pnpm: `npx pnpm@10.28.0 <команда>` (в Node 25 нет corepack).
- Next/SWC: перед `dev`, `build`, `typecheck` задайте `SWC_NATIVE_BINDING_CACHE=%USERPROFILE%\.cache\swc` (в PowerShell: `$env:SWC_NATIVE_BINDING_CACHE="$env:USERPROFILE\.cache\swc"`). Без этого — `ERR_SWC_NATIVE_CACHE`.
- Превью: `.claude/launch.json` запускает `next dev` с этой переменной (имя конфигурации `web`, порт 3000).
- Playwright: `PW_CHANNEL=msedge` (системный Edge, Chromium не скачан).
- Git: глобальная идентичность не настроена. Коммиты делались так: `git -c user.name=Claude -c user.email=noreply@anthropic.com commit ...` с подписью `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Пуш работает (владелец залогинился через Git Credential Manager).
- Prettier на файлы, которые вы не меняли, не запускайте: многие файлы в репозитории не отформатированы, и он раздувает diff. Форматируйте только свои файлы; если задели чужие — `git checkout -- <файл>`.
- PowerShell: многострочные замены через `.Replace()` спотыкаются о CRLF в рабочей копии — надёжнее инструмент Edit. Пути со скобками (`src/app/[locale]/...`) — через `-LiteralPath`.
- `pnpm vectors:check` на Windows падает из-за CRLF, хотя данные совпадают (`git diff --ignore-cr-at-eol` пустой). Это известно, см. задачи ниже.

## Как владелец работает

- Пишет по-русски, отвечать по-русски. Решения принимает через вопросы с вариантами (AskUserQuestion), с рекомендуемым вариантом первым.
- Коммитить можно по этапам; **пушить — только когда попросит** (обычно «запушь»).
- Любит проверку по скриншотам: `pnpm shots` (нужен запущенный `pnpm dev`) кладёт полные снимки 1440 и 390 px в `test-results/shots/`. Скриншоты присылает и сам — их надо воспроизвести и исправить (как с полями лифта в быстрой форме).
- Ревью дизайна — скилл `impeccable`, команда `critique`: две независимые оценки сабагентами (дизайн-ревью и детектор + браузер), сводный отчёт, снимок в `.impeccable/critique/`, в конце вопросы. История: 25 → 29 → 31 → 32 → 33 из 40. После пятого круга владелец решил ревью больше не гонять — следующий прогон только по его просьбе.
- Владелец не хочет «продавать» цифрами: лендинг продаёт сервис, цены и ставки — в конфигураторе и на `/tarife`.

## Ключевые решения последних дней (подробно в decisions.md §9)

- D30–D35: лендинг продаёт сервис; два способа заказать вместо трёх тарифов; услуги без цен; ставки — отдельная страница; «Ce include prețul?» у каждой вилки; блок «Cum avem grijă» с рисунками до появления фото.
- D36–D37: шаг «Tarif» → вопрос об оценке («Evaluare»); полная защита вне MVP; смета проще.
- D38: «preț maxim garantat» вместо «preț fix».
- D39: выезд специалиста бесплатный в «Ne ocupăm de tot», иначе 150 лей с зачётом; ящики требуют выезда.
- D40: блок заботы — компактный список с рисунками.
- D41: при известном максимуме (вещи перечислены поштучно + выбрана оценка) талон показывает крупно максимум, мелко «de la …»; верх вилки не показывается. Расчёт — `src/domain/cap.ts`.
- D42: если на оценке вещей больше — новый максимум до переезда, отказ бесплатно, 150 лей за визит возвращаем.
- D43: пример на лендинге остаётся «по комнатам» с подписью «ориентировочно».
- D44: оценка не позже чем за 7 дней до переезда, ящики отдельно (по умолчанию за 3 дня, по желанию клиента).

## Задачи, вынесенные отдельно

Две задачи были предложены как отдельные сессии (кнопки в интерфейсе). Если их ещё не запускали:
1. Ключи с точкой в разделе `paths` переводов (`"from.floor"` и т. п.) — next-intl пишет `INVALID_KEY` на каждой странице. Нужно перевести в вложенные объекты и поправить места, где ключ собирается из пути ответа.
