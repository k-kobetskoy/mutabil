# Mutabil

Сайт сервиса переездов в Клуже: лендинг, который продаёт сервис, и конфигуратор, который объясняет каждую цифру сметы. Два способа заказать: «Configurezi tu» (сам собираешь переезд и сразу видишь цену) и «Ne ocupăm de tot» (короткая заявка, специалист приезжает и называет цену).

Что и почему решено — в [`docs/decisions.md`](docs/decisions.md) (D1–D44). Ход переработки интерфейса и все ревью — в [`docs/ux-revision-plan.md`](docs/ux-revision-plan.md). Позиционирование и принципы — в [`PRODUCT.md`](PRODUCT.md).

## Запуск

Нужны Node 22 или новее, pnpm 10.28 (версия закреплена в `package.json`) и, для `api/`, Go 1.25.

```bash
pnpm install
pnpm dev
```

Откройте http://localhost:3000/ro (английская версия — `/en`).

Продакшн-сборка, как в Docker:

```bash
pnpm build && pnpm start
```

`pnpm start` запускает standalone-сервер скриптом `scripts/start-standalone.sh`. Не передавайте `HOSTNAME=127.0.0.1`: с ним румынские адреса уходят в бесконечный редирект (подробности в комментарии в скрипте).

### Windows

- Если `pnpm` не запускается (в Node 25 нет corepack), используйте `npx pnpm@10.28.0 <команда>`.
- Если `next dev` или `typecheck` падают с `ERR_SWC_NATIVE_CACHE`, укажите кеш SWC в домашней папке: `SWC_NATIVE_BINDING_CACHE=%USERPROFILE%\.cache\swc`.
- Для `pnpm start` нужен `sh` (Git Bash).

## Устройство

```
config/          ставки, каталог, районы, машины, лифты, правила, шаги (JSON)
messages/        тексты RO и EN
src/domain/      расчёт: объём, машина, время, бригада, цена, вилка, максимум (без React)
src/contract/    Zod-схемы заказа и сметы → contract/openapi.yaml → api/ (Go)
src/config/      загрузка и проверка конфигов
src/features/    лендинг, конфигуратор, заявка «под ключ», фото с разметкой
src/ui/          общие компоненты на React Aria
src/services/    интерфейсы сервисов и заглушки (заказ, слоты, адреса, файлы)
tests/           unit, golden, e2e
```

Сервер — единственный авторитет по цене (D23): клиент считает тем же кодом из `src/domain`, а заглушка заказа пересчитывает смету при отправке.

## Где менять ставки и каталог

Все числа живут в `config/*.json`. Каждое значение записано как `{ value, unit, source, verified, note }`: откуда взято и проверено ли. Сейчас почти все значения `verified: false` — это заглушки до проверки на реальных заказах.

| Что                                                                                                                        | Файл                    |
| -------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| Ставки бригады и машин, ящики, материалы, упаковка, сборка, оценка (цена, потолок, срок), выходные, коэффициент «под ключ» | `config/pricing.json`   |
| Предметы (объём, вес, сборка), пресеты квартир                                                                             | `config/catalog.json`   |
| Районы и пригороды, ограничения въезда                                                                                     | `config/zones.json`     |
| Машины                                                                                                                     | `config/vehicles.json`  |
| Классы лифтов                                                                                                              | `config/elevators.json` |
| Нормы времени                                                                                                              | `config/time.json`      |
| Слоты, лимиты фото и видео, вид цены по умолчанию                                                                          | `config/app.json`       |

После изменения чисел:

```bash
pnpm test           # проверка конфигов и сценариев
pnpm vectors:gen    # если поменялись результаты расчёта — обновить золотые векторы и посмотреть diff
```

Если меняется форма конфига (новое поле), обновите схему в `src/config/schema.ts` и выполните `pnpm contract:gen`.

## Как добавить шаг

1. Опишите шаг в `config/steps.json`: `id`, адрес на двух языках (`slug.ro`, `slug.en`), в каких режимах он есть (`modes`) и какие ответы обязательны (`required`).
2. Сделайте компонент в `src/features/configurator/steps/` и добавьте его в `BODIES` в `StepScreen.tsx`.
3. Добавьте тексты в `messages/ro.json` и `messages/en.json`: `steps.<id>.title`, `stage.<id>` и сообщения проверки. Тест `tests/unit/messages.test.ts` следит, чтобы ключи в RO и EN совпадали.

## Как добавить правило

Правила — в `config/rules.json`: условие на JSONLogic (`when`, при необходимости `each` для обоих концов маршрута) и список эффектов `then` из закрытого словаря: `assume`, `addTask`, `restrictOptions`, `setDefault`, `hint`, `explain`, `hideStep`. Тексты эффектов — ключи в `messages`. Движок — `src/domain/rules/engine.ts`; добавьте сценарий в тесты и, если правило меняет цену, обновите золотые векторы.

## Перед запуском

- Реквизиты компании, телефон и e-mail в футере (сейчас «în curând»).
- Страницы политики конфиденциальности, условий и правил защиты.
- Юридические формулировки, в том числе «preț maxim garantat», — на проверку юристу (D24, D38).
- Настоящие фотографии для блока «Cum avem grijă» (список кадров в `docs/ux-revision-plan.md`).
- Проверить ставки и нормы в `config/` (`verified: false`) на первых заказах.
- Реальные сервисы вместо заглушек в `src/services/` (заказ, слоты, загрузка файлов) и сервер на Go.
